# Asset Checker

Проверка графических и видеоассетов на соответствие требованиям площадок перед публикацией. Загружаешь файл — получаешь список плейсментов, куда он проходит, и разбор по каждому несовпадению.

Одна HTML-страница без зависимостей и без сервера. Файлы никуда не отправляются: разбор идёт в браузере.

## Что проверяется

**Статика**
- разрешение, пиксель в пиксель
- вес относительно лимита площадки
- формат контейнера
- альфа-канал — разбором заголовка `IHDR` у PNG
- цветовая модель RGB / CMYK / Grayscale — разбором маркера `SOF` у JPEG
- поля по краям — эвристикой, подсчётом однотонных рядов пикселей

**Видео**
- разрешение, вес, контейнер
- кодек — из `stsd`, с запасным поиском по сигнатурам `avcC` / `hvcC` / `av1C` / `vpcC`
- частота кадров — из `stts` и `mdhd`, с запасным подсчётом реальных кадров через `requestVideoFrameCallback`
- длительность
- наличие и кодек звуковой дорожки — справочно, на вердикт не влияет

## Правила соответствия

Разрешение засчитывается при точном совпадении **или** при большем размере с тем же соотношением сторон, если файл укладывается в лимит веса: файл 2880 × 1620 закрывает слот 1920 × 1080. Слоты с фиксированной вёрсткой — аватар, thumbnail, обложка Behance — помечены `exact: true` и апскейл не принимают.

JPEG считается основным форматом для статики, PNG допустимым. H.264 — основной кодек, H.265 допустимый.

Плейсменты, которые не подошли, сортируются по близости к файлу: разница соотношений сторон весит вдесятеро больше разницы масштаба, а слоты под другой тип медиа уходят вниз. Для файла 16 : 9 сверху окажутся 16 : 9 слоты, а не первая попавшаяся площадка.

## Переименование

Поле проекта в шапке, поле контекста у каждого файла, номер из позиции в очереди, площадка из выбранного плейсмента, размеры из самого файла:

```
1-NordicRail-HeroShot-Behance-2880-1620.jpg
2-NordicRail-LogoReveal-Ramotion-1920-1080.mp4
```

Кириллица транслитерируется, пробелы схлопываются в PascalCase. Кнопка собирает ZIP с готовыми именами прямо в браузере — архив пишется вручную методом store, без сжатия, поскольку медиа уже сжато. При удалении файла из очереди нумерация пересобирается автоматически.

## Как добавить или изменить плейсмент

Все требования лежат одним массивом `SPECS` в начале `<script>`. Одна запись — один слот:

```js
{
  cat:    'Behance',      // площадка, она же категория в селекторе
  group:  'Static',       // тип ассета, подкатегория
  place:  'Static',       // подпись плейсмента
  ar:     '16 × 9',       // подпись соотношения
  w: 2880, h: 1620,       // требуемое разрешение
  kind:   'image',        // 'image' | 'video' | 'any'
  max:    10*MB,          // лимит веса
  rec:    1*MB,           // рекомендуемый вес, необязательно
  formats:['png'],        // допустимые контейнеры
  rgb:     true,          // требовать RGB
  noAlpha: true,          // запретить альфа-канал
  exact:   true,          // запретить апскейл
  codec:  'h264',         // требуемый кодек
  fps:     60,
  minDur:  3, maxDur: 60, // длительность в секундах
  padding:'24px 12px',    // или 'none'
  note:   'произвольная пометка'
}
```

Обязательны только `cat`, `group`, `place`, `ar`, `w`, `h`, `kind`, `max`, `formats`. Остальные поля включают соответствующие проверки.

Рядом лежат два переключателя:

```js
const JPEG_PRIMARY_FOR_STATIC = true;                    // JPEG первым у всей статики
const CODEC_OK = {h264:['H.264','H.265'], h265:['H.265']}; // взаимозаменяемые кодеки
```

## Запуск

Открыть `index.html` в браузере. Сборка не нужна.

Шрифт IBM Plex Mono подтягивается с Google Fonts; без сети подставляется системный моноширинный.

## Развёртывание на GitHub Pages

Settings → Pages → Source: `Deploy from a branch`, ветка `main`, папка `/ (root)`. Через минуту страница будет доступна по адресу вида `https://<пользователь>.github.io/asset-checker/`.

## Поддержка форматов

Разбор метаданных рассчитан на контейнеры ISO BMFF: `.mp4`, `.mov`, `.m4v`. У `.webm` контейнер Matroska, метаданные этим путём не читаются — разрешение и длительность определятся, кодек и частота кадров нет.
